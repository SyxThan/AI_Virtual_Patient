# Frontend UI (Next.js App Router)

UI only. **No business logic or data access in the web app** (ADR-0001); everything
goes through FastAPI. Next.js route handlers hold no business logic.

## Screens (routes under `apps/web/src/app/`)
1. `/setup` — choose case, role, mode; create a session (`POST /sessions`).
2. `/session/[id]` — the interview: transcript + turn input (text first; turn-based voice is P2).
3. `/debrief/[id]` — OSCE result + cited debrief.

## Conventions
- Visual system (Slice 15, "Bento Clinical"): read `docs/specs/ui-design.md` first. Use the tokens (`bg-canvas`, `text-ink`, `bg-primary`…) and the primitives in `components/ui/` (`Button`/`buttonClass`, `Tile`, `Card`, `Badge`, `PageShell`); never raw `gray-*`/`blue-*` palettes. No new npm dependencies.
- TypeScript **strict**. Server Components by default; add `"use client"` only when needed. Dynamic route params are a Promise in Next 16 — `const { id } = await params`.
- Styling: **Tailwind v4** (`@import "tailwindcss"` in `globals.css`, `@tailwindcss/postcss`). 
- i18n: all Vietnamese strings in `apps/web/messages/vi.json`; import and reference keys — no hard-coded UI text in components.
- API access: use the **generated client** in `src/lib/api-client/` (regenerated by `make gen-client` from the FastAPI OpenAPI schema). Do not hand-write fetch calls or API types; do not hand-edit the generated client. Env: `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_WS_URL`.
- Auth: browser uses `supabase-js` for **sign-in only** (ADR-0008); send the token as `Authorization: Bearer` to the API. Guest sessions carry `X-Guest-Token`.

## Errors & states (T-UX-02)
- Handle loading, retry and empty states; show API errors (the `{error:{code,message}}` shape); never show a false success.

## Lint/build
- `cd apps/web; npm run lint; npm run build`. ESLint uses flat config from `eslint-config-next` (spread `core-web-vitals` + `typescript`); `next lint` is removed in Next 16 — the `lint` script calls `eslint .`.

## Layer 2 (do not build without a scope-gate)
- 3D avatar (Three.js in a client-only component via `dynamic(..., { ssr: false })`), vitals display, exam/raycasting, full-duplex voice. Keep these out of the MVP UI.
