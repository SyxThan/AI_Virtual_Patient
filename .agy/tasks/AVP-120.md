# AVP-120 Cross-slice tests: guest -> claim -> history -> progress (Slice 10 + 11)

## Goal
One new pytest file that checks Slice 10 (sign-in, claim) and Slice 11 (history, progress) work together, per quality-gates T-E2E-01, T-AUTH-02, T-HIST-01, T-SEC-01. In-process only.

## Requirements
Do NOT run any shell command other than `python -m pytest`. Never edit application code or other tests.
Harness helper `make_h()`:
- start from `_signed_in_harness()` (imported from tests.test_auth);
- override `me.get_profile_repo` with `FakeProfileRepo(h.store, profiles)` (from tests.test_me);
- override `sessions.get_history_repo` with `InMemoryHistoryRepository(h.store.sessions, h.store.evals)`;
- override `debriefs.get_display_name_lookup` with a lookup over that same profiles dict.

Guest auth is `{"X-Guest-Token": token}` from POST /api/v1/sessions; a user is `_bearer(USER_A)`. Synthetic Vietnamese questions only.

Tests:
1. `test_guest_session_claimed_appears_in_history`:
   - guest creates a session, sends 2 turns, then finish;
   - A's GET /api/v1/sessions does not list it;
   - A claims it (POST /sessions/{id}/claim, Bearer A + X-Guest-Token) -> 200;
   - A's list now contains it with evaluation_status "done";
   - its total_score and critical_missed equal those of GET /evaluation.
2. `test_after_claim_guest_token_alone_is_denied`: after the claim, X-Guest-Token alone gets 404 on GET /sessions/{id}; Bearer A alone gets 200 on GET /sessions/{id}, /turns, /evaluation, /debrief and /debrief/pdf.
3. `test_user_b_cannot_see_or_claim`:
   - B's list is empty;
   - B claiming with the right guest token after A's claim gets 404;
   - B gets 404 on GET /sessions/{id} and /debrief/pdf;
   - B's /sessions/progress has no attempts.
4. `test_signed_in_sessions_ordered_and_progress_matches`:
   - A creates 2 sessions with Bearer, sends 1 turn in each, finishes both;
   - the list is newest first;
   - /sessions/progress has 2 attempts in chronological order, each score equal to that session's GET /evaluation total_score.
5. `test_bad_or_missing_bearer`: on GET /sessions, GET /sessions/progress and GET /me,
   - no header gets 401 with detail code "AUTH_REQUIRED";
   - `make_token(USER_A, exp_in=-10)` gets 401 with code "AUTH_INVALID".
6. `test_pdf_uses_display_name_after_claim`:
   - A sets PATCH /me display_name "Người học thử" and then claims a finished guest session;
   - GET /debrief/pdf -> 200 application/pdf;
   - the display-name lookup was called with USER_A.

If an assertion fails because the API behaves differently from this brief, do NOT change app code: mark that test `pytest.mark.xfail(reason=..., strict=True)` and explain in the report.
