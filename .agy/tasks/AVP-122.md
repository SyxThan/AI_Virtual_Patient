# AVP-122 Cross-slice tests for Slice 12 (guide, exam limit) and Slice 13 (delete, privacy)

## Goal
Add one new pytest file that checks the guide and exam time limit (Slice 12) and deletion (Slice 13) against the quality gates T-PRIV-01, T-SEC-01, T-UX-02 and T-SESSION-01. It runs in-process only.

## Context
Read these files and do not modify them:
- apps/api/tests/test_privacy.py: the `h` fixture wiring, FakePrivacyRepo, `_session_with_data`, `_children`, SESSION_ROUTES usage
- apps/api/tests/test_auth.py: `_signed_in_harness`, `_bearer`, USER_A, USER_B, SESSION_ROUTES
- apps/api/tests/test_exam_time_limit.py: how `exam_time_limit_s` is monkeypatched on `get_settings()`
- apps/api/avp_api/routers/guide.py and apps/api/avp_api/services/guide_service.py

## Allowed paths
- apps/api/tests/test_slice12_13_flow.py
- .agy/reports/AVP-122.md

## Requirements
- Do NOT run ANY shell command (not even pytest, ls or git). Headless mode denies them and the run fails. Only read files and write the two allowed files; the wrapper runs the acceptance command.
- Never edit application code or other tests. Use synthetic Vietnamese questions only.

Write a helper `make_h()` that copies the `h` fixture of tests/test_privacy.py: start from `_signed_in_harness()`, use `FakePrivacyRepo` and `FakeProfileRepo`, and set `deleter=None`. Then also override `guide.get_session_repo` with `FakeSessionRepo(h.store)` from tests.test_evaluation_api.

To make a session "old", set `h.store.sessions[sid].started_at` to `datetime.now(UTC) - timedelta(seconds=120)`.

Tests:
1. `test_exam_limit_blocks_turns_actions_and_vitals_but_not_finish`
   - Set the limit to 60 and create an exam-mode session (`{"consent": true, "mode": "exam"}`), then backdate it.
   - POST /turns, POST /actions `{"action":"examine_region","region":"mouth_throat"}` and POST /vitals/events `{"event":"ORDER_ANTIPYRETIC"}` each return 409 with code "TIME_LIMIT_REACHED". No new turn is stored.
   - GET /guide returns `time_limit_s == 60`.
   - POST /finish returns 200 and GET /evaluation returns 200 with status "done".
2. `test_guided_mode_never_limited`: the same backdate with limit 60 in guided mode, and turns, actions and vitals all return 200.
3. `test_no_limit_by_default`: an exam session backdated by 10 hours with the limit None still gets turn 200.
4. `test_guide_checklist_by_mode`
   - Guided: `items` is non-empty and every item has criterion_id, domain and title. The response's review status is "draft".
   - Exam: `items == []`.
   - A wrong guest token and USER_B's bearer get 404 on /guide.
5. `test_delete_signed_in_session_removes_it_everywhere` (T-PRIV-01)
   - USER_A finishes a session with data (`_session_with_data` with `_bearer(USER_A)`), then GETs /guide.
   - DELETE returns 204.
   - These routes then return 404 for A: /sessions/{id}, /guide, /turns, /vitals, /evaluation, /debrief, /debrief/pdf.
   - GET /api/v1/sessions does not list it.
   - /sessions/progress has 0 attempts.
   - `_children(h, sid)` is all zero.
6. `test_delete_me_keeps_other_users_data`
   - A has 2 finished sessions and B has 1.
   - A's DELETE /api/v1/me returns 200 with `sessions_deleted == 2` and `account_deleted is False`.
   - A's list is then empty.
   - B's session still returns 200 and is listed for B.
7. `test_guest_delete_then_claim_is_404`: a guest deletes its own session (204). A claim by USER_A with that guest token then returns 404.
8. `test_delete_while_evaluation_pending_does_not_crash`
   - Use `_signed_in_harness` wiring, but build the base harness with run_jobs=False. Construct it via `tests.test_e2e_flow.make_harness(run_jobs=False)` plus the same overrides.
   - Guest finishes, then deletes (204).
   - `h.run_job(h.store.jobs[0].id)` if a job remains must not raise.

If an assertion fails because the API behaves differently from this brief, do NOT change app code. Mark that test `pytest.mark.xfail(reason=..., strict=True)` and explain it in the report.

## Acceptance command
`cd apps/api && python -m pytest -q`

## Out of scope
