# ADR-0003: Case as one JSON file with tiered guardrails

- Status: Accepted
- Date: 2026-11-09
- Deciders: Team TRINITY (human), Claude Code
- Related: AVP-005; CLAUDE.md "Hard rules" 1-2; docs/specs/case-schema.md, guardrails.md

## Context
Medical safety is the product's core promise: the Patient Agent must never invent
symptoms, vitals, lab values or doses, and an unlisted clinical fact must be
treated as unknown (neither confirmed nor denied), never an invented "no".

## Decision
We will represent each case as **one JSON file** in `data/cases/`, validated by
`schemas/case.schema.json`, carrying a `review.status`. The Patient Agent answers
in three tiers: **tier 1** states only facts in the case JSON; **tier 2** may
improvise non-medical persona/social detail; **tier 3** uses fixed fallback lines
for anything unknown. Raw sources in `data/source/` are read-only inputs and are
git-ignored. Clinical text generated by an agent stays `draft` /
`origin: author_added` until a clinician reviews it.

## Consequences
- Guardrails are checkable against a schema and a known set of facts.
- Red-team tests can assert "no invented unknowns" (AVP-011).
- Authors can add non-clinical colour without touching clinical safety.

## Alternatives considered
- Free-form prompt per case: rejected — unverifiable, invites hallucination.
- Let the LLM answer "no" to unlisted symptoms (as the proposal suggested):
  rejected — see guardrails.md; unknown ≠ negative.
